# 板材套裁与余料复用系统

板式家具厂开料套裁：板材台账 → 订单部件需求 → 自动套裁（**先吃边角余料、再开整板**）→
余料登记复用台账 → 变更单只改未开料部分并重算耗板 → 月末利用率两个口径对账。

- 前端：Vue 3 + Vite + TypeScript
- 后端：Fastify + better-sqlite3，前后端分层
- 纯函数模块：`lib/packing.ts`（套裁方案）、`modules/remnants.ts`（余料匹配）、
  `modules/changes.ts`（变更重算）、`modules/stats.ts`（利用率统计）
- **长度一律整数毫米，面积一律整数平方毫米；利用率以千分比整数存储，展示层换算，无浮点误差**
- 锯路 3mm、最小可登记余料短边 100mm（见 `server/src/lib/geometry.ts`）

## 目录结构

```

    modules/planning.ts 下单 / 套裁预览 / 确认开料事务
    modules/remnants.ts 余料台账查询 / “先吃哪块最省”匹配试算
```

## 启动方式

需要 Node.js ≥ 18（开发机为 v22）。首次使用先安装依赖并灌种子数据：

```bash
# 1. 安装前后端依赖
npm run install:all

# 2. 灌入种子数据（5 种规格板材、10 个订单其中 2 单改过单、一批边角料）
npm run seed

# 3a. 开发模式（同时起后端 3210 与前端 5210，前端 /api 自动代理）
npm run dev
#   浏览器打开 http://localhost:5210

# 3b. 厂里电脑单机使用（推荐）：先构建前端，再由后端一并托管
npm run build:web
npm start
#   浏览器打开 http://localhost:3210
```

数据库文件在 `server/data/panel.db`。想恢复演示数据，重新执行 `npm run seed` 即可
（会清库重建）。

## 验收步骤（对照需求）

1. **开一单看整板数和余料登记**
   打开任一待开料订单（如 SO-2609-008）→「生成套裁预览」：显示新开整板几张、
   先吃哪几块余料（标余料 id）、切完登记几块边角料及尺寸位置；「确认开料」后
   「余料复用台账」里能查到新登记的绿“可用”料，被吃掉的余料变灰“已消耗”，
   板材台账整板库存同步扣减。

2. **余料有货时再开一单**
   新建一单只填小件（如 9mm 密度板 450×150 抽屉板），预览可见 **0 张整板、
   全部先吃余料**；或用「余料复用台账 → 余料匹配试算」查看“先吃哪块最省”的
   顺位与浪费面积。不同厚度/材质的余料不会串用。

3. **改单加两块层板，已开料部分不动**
   在已开完的订单（如 SO-2609-004）提交追加变更：需求行里“已开”列数字不变，
   只增加“未开”；尝试减少一个已开完的部件会被明确拒绝（已开料的不许动）。

4. **改完耗板数重算**
   变更提交后提示“累计耗板 X 张 → Y 张（已开料耗 N 张不动，未开部分重排）”，
   「变更记录」表留痕（版本、±数量、前后耗板数、备注）。之后确认开料只切未开部分，
   方案产生新版本，历史版本保留可追溯。

5. **月底利用率两个口径对账**
   「月末利用率」页：按整张数 = 整板上部件面积 ÷ 新开整板面积；
   按面积 = 全部部件面积 ÷（新开整板面积 + 复用余料面积）。
   下方“按规格拆行核对”各列纵向累加等于月总，张数可与板材库存扣减逐一对上。

## 套裁与复用规则

- 部件可旋转 90°；占位 = 净尺寸 + 3mm 锯路，部件图仍显示净尺寸。
- 每块板切完用自由矩形差集 + 相邻共边合并求出真实余料矩形，短边 < 100mm 的碎料不登记。
- 引擎跑 6 种确定性排序策略选最优：新开整板最少 → 余料利用面积最大 → 余料更整块。
- 余料动用顺序：能装下的候选中浪费面积最小 → 短边最接近 → 小料优先（留大料给大单）。
- 余料只在**同规格同材质**（同一 spec_id）订单间复用。
- 确认开料是单事务：吃余料（标记 consumed）、扣整板库存、登记新余料（带来源订单、
  父余料溯源、存放位置）、回写各部件 `cut_qty`，任何一步失败全部回滚。
